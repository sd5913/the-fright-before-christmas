## 已准备的内容

- 独立 `backend/`，使用 Node.js 24、Express、PostgreSQL，根目录 Astro 依赖不变。
- 提交成绩、读取排行榜、检查数据库就绪状态；参数校验、同局去重、并发提交处理、负分、稳定排序、跨域和请求限制。
- Docker Compose：独立 API、独立数据库卷、数据库就绪后启动 API，API 只发布在服务器回环地址 `127.0.0.1:3107`。
- 根据服务器资源设置 API 160 MiB、PostgreSQL 128 MiB、各 0.5 CPU 上限；数据库缓冲与最大连接数相应缩减。
- 事务迁移自动建表；迁移文件有校验，不在启动时清空成绩。SQL 参数化，数据库口令通过环境配置传入，不进入前端代码。
- 不写 Unity 示例脚本，不修改 `Unity/` 或 `public/game/`。

Partner 需要的内容集中在 [backend/API.md](../backend/API.md)：正式地址、字段、数据类型、调用时机、响应、错误码、重试和跨域规则。

## 宝塔部署与维护步骤

1. 确认登录的是用户的阿里云服务器，检查主域名站点的实际反向代理类型、证书、现有配置与占用端口。当前主域名已有圣诞树页面，保留其根路径、文件和 TLS 设置。
2. 将后端部署到独立目录，例如 `/opt/tfbc/backend`。该目录只放本项目后端。上传内容包括锁文件、源代码、迁移、Dockerfile、Compose 文件、脚本和部署说明；排除本地 `.env`、`node_modules`、测试数据和备份。
3. 在服务器独立生成 `.env` 和随机数据库密码。若服务器没有 Node，可从该目录执行：

   ```sh
   docker run --rm -v "$PWD:/work" -w /work node:24-bookworm-slim node scripts/setup-env.js
   ```

   不输出口令；不覆盖已有 `.env`。首次部署后保持同一个数据库口令和数据卷。
4. 核对 `CORS_ORIGINS`，包含正式网站 `https://tfbc.darketomaly.com`。检查 3107 是否空闲；若改用其他端口，同时调整 `.env` 的 `API_HOST_PORT` 和代理 upstream。
5. `docker compose up -d --build --wait`。确认服务健康，再检查服务器本机的 `/tfbc-api/health` 和空榜查询。数据库不发布公网端口。
6. 备份站点原配置。在原 **HTTPS server 块内**增加 [baota-nginx.conf](../backend/deploy/baota-nginx.conf) 中的两个 location；这是路径片段，不是完整站点文件。不得替换既有 `location /`、证书或站点根目录。
7. 该片段假设宝塔 Nginx 在宿主机运行。若反向代理本身在容器中，先确认容器网络和可达 upstream，再选用对应连接方式，不直接照抄 `127.0.0.1`。若实际是 Apache，也需按实际服务器配置生成路径代理。
8. 检查配置语法通过后 reload。通过公开域名验证健康、读取、浏览器 POST 预检；对主域名根路径做回归检查。
9. 在隔离的测试数据库验证完整写入与重试，不在正式榜单插入演示成绩。首次生产榜单应为空；上线后真实成绩才写入。
10. 执行一次数据库备份并验证文件可读。记录部署提交、镜像和健康检查结果，再把正式 API 文档交给 partner。

实际 Nginx 站点文件名为 `/www/server/panel/vhost/nginx/120.55.98.74_3000.conf`，其中绑定了 `metapool.cloud` 和 HTTPS。没有创建或替换根路径站点；只在原 server 块内加入 `include /opt/tfbc/backend/deploy/baota-nginx.conf;`。操作脚本见 [install-proxy.py](../backend/deploy/install-proxy.py)，包含备份、语法检查、根页面哈希对比及失败回退。

## 简化协作的约定

- Partner 的 #9 只需接收 API 地址与文档，负责在自己游戏结束时提交 `runId/playerName/score`。
- `runId` 每局生成一次、重试沿用，服务器用它防止重复写入；不要求改动游戏其他部分。
- 暂按每局成绩排名；不按名字合并个人最高分。没有登录时同名不代表同一玩家。
- 不依赖新游戏事件。#13 页面首次进入或用户刷新时读取真实榜单即可；结算自动刷新以后再另行约定。
- Unity 构建不会自动读取 Astro 的 `PUBLIC_*` 环境变量。API 地址需由 partner 在其接入方式中配置。
